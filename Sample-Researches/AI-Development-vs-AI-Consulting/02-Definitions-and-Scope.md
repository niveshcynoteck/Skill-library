# 1. Definitions & Scope

| Dimension | AI Consulting | AI Development |
|---|---|---|
| **Core question** | "What should we build and why?" | "How do we build it?" |
| **Focus** | Strategy, roadmap, governance, adoption | Architecture, code, models, deployment |
| **Deliverable** | Diagnosis, roadmap, recommendations, decisions | Working software, deployed systems, integrations |
| **Engagement length** | Weeks (strategy) | Months (build) |
| **Measured by** | Business outcomes and ROI | Technical performance and reliability |
| **Risk level** | Low | Medium–High |

Sources: [1][2][7][8][9]

- **AI consultants** analyse the business, identify which problems AI should solve, run build-vs-buy analysis, select vendors, and produce a decision document or roadmap. They may never write production code [10][11].
- **AI developers/engineers** take a defined brief and turn it into production systems: backend services, API integrations, database schemas, prompt/agent orchestration, evaluation harnesses, monitoring, and maintenance [10][12].

## The most common hiring mistake

> **Opinion (multiple practitioner sources):** The most common hiring mistake is confusing the two. Hiring a strategy-only consultant when you need software leaves you with a roadmap and no system; hiring a developer with no strategic framing can produce a technically beautiful answer to the wrong problem [3][8][11].

## Where the boundary sits

- The boundary is **not** about intelligence or seniority — it is about the primary deliverable: **a decision** (consulting) versus **working software** (development) [3].
- Many practitioners argue the two roles are best combined in one person ("engineer-consultant") for small and mid-size engagements, to avoid the translation loss that happens when a consultant's diagnosis is handed to a separate build team [5][8].
- Advisory-only consulting is a real sub-type: it produces strategy, roadmaps, and governance frameworks but no code — appropriate for regulated industries, board-level direction, and organizations with strong in-house engineering [8][11].
