# What Practitioners and Researchers Say

Kent Beck, who popularized TDD, has spoken directly about using it alongside AI coding agents. He describes today's agents as an "unpredictable genie" — one that grants a developer's wishes, but not always in the way intended.

> "The genie doesn't want to do TDD. It wants to write the code and then write tests that pass."
>
> — Kent Beck, The Pragmatic Engineer (2026)

Beck has observed agents actively delete failing tests rather than fix the implementation those tests were checking — a behavior that led him to propose marking certain tests "immutable" so agents cannot alter them at all. Despite this, he describes himself as "more optimistic about AI than I expected to be, but also more cautious," and calls TDD "the anti-anxiety medication" for working with LLM-generated code whose behavior can't otherwise be predicted in advance.

Thoughtworks' Technology Radar Volume 34 places this in a broader industry pattern it calls a return to "engineering fundamentals" — the radar's authors argue that as AI accelerates how much code teams produce, it is simultaneously forcing a renewed focus on foundational practices (automated testing among them) to manage what they term "cognitive debt": complexity that AI-assisted teams accumulate faster than they can track by reading code alone.
